# In-game economy fixes, 2026-09-12

The batch uses the r208022 client and the deployed server compact.
Website payment integration in aaemu-cluster#533 is outside this batch.
Criminal bounty issue #145 remains with the separate crime system work.

## Currency and inventory

- #301: Money debits and credits reject negative amounts. Client bank transfers reject zero, negative, and unsupported point requests.
- Both wallet balances pass the funds and overflow checks before either balance changes.
- Repair checks the full batch cost before durability changes. Duplicate repair references count once.
- Regrade payment must pass before the grade roll. Shipyard materials, output, and money use one inventory mutation.
- #459: Client item IDs resolve through the character inventory. Unwrap and delayed item skills check current ownership.
- A repeated unwrap cannot reset the item lifetime. Unwrap rejects reserved items and bank items without an open bank service.
- Shipyard payment failure allocates no construction IDs. Successful payment installs the construction before item notifications.
- A failed item notification cannot stop the accepted shipyard from its normal spawn path.
- #473: Inventory and bank expansion stop at the last authored step. Unsupported slot types cannot expand capacity.

## Service access

Bank, auction, and mailbox functions record the open interaction target.
Actions need the current object in the same world and instance.
The distance check includes height. Bank, auction, and mailbox access uses 5 metres.
Merchant sales use 3 metres and accept items from the bag only.

The NPC flags and current doodad functions determine which service is available.
Doodad phase changes and object replacement invalidate the old interaction.
All 4 attachment claim routes need an open mailbox.

## Level restrictions

`LevelRestrictions` in `Config.json` controls the values sent to the client and used by the server.
Auction search, bid, post, trade, and mail default to level 10.
Shout, Trade, GroupFind, Region, and Ally chat default to level 15.
Other chat channels keep a zero threshold.

## Auction claim process checks

The MySQL integration suite runs 6 crash cases, with 2 cycles per case.
Each cycle starts a separate test process with the production claim store.
A private SQL trigger pauses the process inside the transaction, after its receipt insert.
The other crash point follows the committed claim and precedes any client response.
The parent process stops the worker, creates a fresh store, and retries the claim twice.
The checks cover sale money, item delivery, stack merge, receipt count, labor, and final item count.
These checks use disposable schemas. They do not stop a live Game process.

The current claim migration already exists in the deployed database.
This batch adds no claim migration and does not rewrite current claim receipts.

## Doodad purchase currency

The r208022 dispatcher at `FUN_393b80d0` uses gold when `coin_item_id` is 0 or `coin_count` is below 1.
Otherwise, it uses the authored item and full coin count.
The gold dialog at `FUN_393b9080` displays `items.price × count`.
The affordability check at `FUN_393bc4e0` uses the same amount.
These addresses use the x2game dump base `0x38ff0000` and the client hashes in the world trade evidence.

The deployed `currency_id` values are all 0, and `currency_configs` contains no rows.
The server rejects unsupported currencies, missing output templates, and zero-priced test designs.
Payment and output use one inventory mutation. A failed grant restores the payment.
The tests cover both absent coin fields, each single absent field, partial coin stacks, and failed output grants.

## Paid buff persistence

A buff save error now aborts the economy checkpoint.
The MySQL test fails the priest buff insert and checks that both the wallet and buff remain unchanged.
Its retry saves the debit and buff in one transaction.
Purchased priest buffs and labor buffs survive repeated restarts before the next save.
A later save also preserves the final minute of an authored long paid buff.

## Labor, crafts, and automatic rewards

Paid skills check labor before effects and again when the synchronous effect batch completes.
The transaction saves the debit with items, paid buffs, harvest state, and other supported results.
It also saves automatic character experience, ability experience, proficiency, and consumed labor before success notifications.
Known failure restores the debit and all prepared rewards.
Asynchronous plot nodes use separate synchronous transactions. The first reward or labor marker pays the skill cost once.

Supported immediate child skills join their parent transaction and pay their own authored labor cost.
Compose and bot reports save their paid state before success callbacks.
Direct doodad placement saves the source item, placement record, and labor together.
Public-farm placement and permitted house placement keep their current labor waivers.
Craft duration starts with the individual craft's authored delay and applies proficiency and skill modifiers once.

The effect audit accepts 1160 of the 1175 paid templates and rejects 15 before effects.
Those exclusions contain 10 labor test skills, Pickpocket, the unavailable dominion claim, Mandragora, and 2 effect stubs.
Pickpocket remains reachable through direct requests or manual item grants in the old source.
The checked compact data contains no acquisition route for its item 15717.
Mandragora has authored hammer items, but the old proc code already prevents normal use.
The exact exclusions and source limits appear in [Paid skill settlement](economy/skill-labor.md).

## Experience recovery

Paid recovery saves its labor cost and recovered experience in one transaction.
Free recovery scrolls need no labor and save their consumption with the recovered experience.
Recovery adds no labor experience, ability experience, or gain multiplier.
Failed transactions restore payment, scrolls, and recoverable experience.

## Database changes

They create `specialty_demand`, `house_tax_receipts`, `dominion_states`, and `bot_reports`, and add nullable `audit_ics_sales.item_count`.

The release SQL review records all 6 script hashes, repeat behavior, and preconditions in the paired cluster repository.
Neither compact database changes in this batch.

## Custom trade and tax rules

The exact client evidence does not establish retail negotiation or late-tax rates.
The user approved a 10 percent late fee and a custom Commerce bonus.
`World.HouseLateFeePercent` defaults to 10.
The server adds the rounded-up fee once during the late grace period. It does not compound the fee.

Commerce rank gives 1 percent negotiation chance per rank, capped at 7 percent.
A successful roll adds 5 percent before interest and maker sharing, rounded down to whole currency units.
The rate is a custom server rule, not a claim about retail behavior.
