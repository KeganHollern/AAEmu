### Confirmed report contract

The native path confirms the complete `CSReportCrimePacket` body for opcode `0x76`:

| Field | Width | Native source |
| --- | --- | --- |
| Evidence object ID | 3 bytes | Evidence object `+0x7c` |
| Selected interaction skill ID | 4 bytes | Interaction caller argument |
| Next phase | 4 bytes | `doodad_funcs.next_phase` |
| Function ID | 4 bytes | `doodad_funcs.id`, called `FuncKey` in AAEmu |
| Message | 2-byte byte count, then UTF-8 | Native maximum is 200 bytes |

The final field is not `actual_func_id`.
The native descriptor loader `39673b90` stores the row ID at `+0`, the actual
function type at `+8`, its object at `+0xc`, `func_skill_id` at `+0x18`, and
`next_phase` at `+0x1c`.

`396f6390` and dispatcher `393bc260`, at call sites `393b40fc` and `393b770a`.

The report function `393bb090` copies these values into the X2Trial cache at

### Server rules

The server checks the current registered evidence object and phase. It rejects
ordinary doodads, stale objects, other worlds, self-reports, missing owners,
forged function data, and invalid kind/point combinations.
It uses the shared skill range calculation, including height and the caster's
model radius. It also uses the current caster-state checks and prisoner state.
The server does not trust a cached client dialog after its evidence changes.

Validation, record creation, point changes, and phase consumption share
`SaveManager.PersistenceSyncRoot`. Concurrent reports cannot consume one phase
twice. Dirty crime IDs use the same list lock as the save path.

Prison admission checks use `Character.IsPrisoner`. This query covers an active
prisoner tag and a stored pending trial, including the `-1` zero-minute marker.
Battlefield queue, matchmaking, invitation, final entry, start reset, and delayed
kill reset paths all check this state. Dungeon requests, system instances,
queued entry, and final loading also check this state.

Justice transfer cancels pending admissions and removes old membership.
It removes captured return positions and dungeon event handlers.
It restores the original faction only for an entered battlefield member.
It explicitly sets the destination instance, including instance `0`, before
it sets the position. It sends an instance-load packet across worlds and a
teleport packet within a world. `WorldSpawnPosition` angles remain in radians.
Old entry, leave, and reset callbacks cannot replace the justice destination.

Court chat uses the current trial instead of the sender's faction channel.
Only its defendant and accepted jurors can speak. Online valid audience members
can receive. An outside sender or audience sender receives `ChatNotInTrial`.
Terminal trials cannot send chat. Final trial packets can still reach the
current audience until the courtroom clears that trial identity.

The speaker rule is a server authorization rule from #518. Native research did
not prove a different rule. The audience check keeps the current 5-metre seat
check and adds same-instance identity. This distance is a retained server rule,
not a newly claimed retail measurement. The change adds no guessed radius for
the defendant or jurors.

A defendant or juror cannot join another courtroom audience before the current
case releases that role. A new audience join first removes old audience membership.
Audience changes and final sends use the persistence lock before trial state.
The trial branch moves jury eligibility checks outside its queue lock.
The lock order is persistence, admission, trial, then queue.
No chat-channel lock remains held while the server reads trial state.
